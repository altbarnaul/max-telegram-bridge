# MAX → Telegram Bridge

*Self-hosted bridge that forwards your [MAX](https://max.ru) messenger chats into a Telegram forum group and sends your Telegram replies back to MAX. Multi-user, one Telegram bot, login by QR code. Russian UI.*

Мост пересылает сообщения из мессенджера MAX в Telegram-группу с темами и отправляет ответы обратно в MAX. Вы поднимаете его у себя: свой Telegram-бот, свой сервер, токены MAX хранятся в вашей базе в зашифрованном виде.

- **Вход в MAX по QR-коду.** Мост становится отдельным WEB-устройством аккаунта; web.max.ru и приложение на телефоне продолжают работать.
- **Темы по типу чата:** Личные / Группы / Каналы.
- **Ответ из Telegram:** Reply на пересланное сообщение уходит в тот же чат MAX.
- **Написать первым:** `/to Имя текст` или `/to +79991234567 текст` в группе моста.
- **Фото** приходят альбомом, остальные вложения — подписью (`[Видео]`, `[Файл: …]`, `[Голосовое]`).
- **Многопользовательский:** один бот обслуживает любое число аккаунтов MAX, у каждого своя группа.

> **Важно.** У MAX нет публичного API для пользовательских аккаунтов. Мост говорит с тем же WebSocket-протоколом, что и web.max.ru (`wss://ws-api.oneme.ru/websocket`). Протокол неофициальный и может поменяться в любой момент; пользуйтесь на свой риск и в рамках правил MAX. Тот, кто держит сервер, технически имеет доступ к переписке всех подключённых аккаунтов — поднимайте мост для себя или для тех, кто вам доверяет.

## Как это работает

```
 MAX (WebSocket, протокол web.max.ru)
        │  по клиенту на каждого пользователя
        ▼
 ┌──────────────────────────── max-bridge ─────────────────────────────┐
 │ SessionManager ── MaxClient × N ──► MessageRouter ──► Telegram Bot  │
 │        ▲                                                  │         │
 │        └───────────── ответы (Reply, /to) ◄───────────────┘         │
 │                 SQLite: пользователи, группы, маппинг сообщений      │
 └──────────────────────────────────────────────────────────────────────┘
        ▼
 Telegram: форум-группа пользователя, 4 темы
```

1. Пользователь пишет боту `/start` → бот открывает WebSocket к MAX как новое WEB-устройство и присылает QR-код (живёт 2 минуты, истёк — бот пришлёт следующий).
2. Пользователь сканирует QR телефоном с MAX и подтверждает вход. Мост получает собственный токен, шифрует его (Fernet) и сохраняет вместе со своим `device_id`.
3. Пользователь создаёт форум-группу, добавляет бота админом с правом «Управление темами» и пишет `/setup` → бот создаёт 4 темы, пересылка запускается.

Пошаговая инструкция для конечного пользователя — [docs/GUIDE.md](docs/GUIDE.md).

### Маршрутизация

| Тип чата MAX | Тема в Telegram |
|---|---|
| `DIALOG` | Личные |
| `CHAT` / `GROUP` / `MULTIDIALOG` | Группы |
| `CHANNEL` | Каналы |

Тема «Комментарии» создаётся заранее, но комментарии к постам каналов мост пока не разбирает отдельно.

Имя отправителя берётся из контактов, потом из прошлых сообщений, потом запрашивается у MAX. Тип и название чата, которого нет в стартовом снапшоте, тоже запрашиваются у MAX и кешируются в базе.

### Токен MAX

Подключение — только QR-входом (`/login`). Токен, скопированный из браузера, не живёт: MAX ротирует токен при входе с другого устройства и отзывает всю цепочку, когда браузер снова предъявит свою копию — разлогинит и мост, и web.max.ru.

Мост сохраняет каждый ротированный токен и раз в сутки переподключается. Если MAX всё же отозвал вход, сессия останавливается, статус → `expired`, пользователь получает «нажмите /login»; после повторного QR-входа пересылка продолжается в ту же группу.

## Быстрый старт

### 1. Telegram-бот

1. В [@BotFather](https://t.me/BotFather): `/newbot` → получите токен.
2. По желанию задайте команды (`/setcommands`):
   ```
   start - Подключить MAX
   login - Войти в MAX по QR-коду
   status - Статус подключения
   stop - Приостановить пересылку
   setup - Создать темы (в группе)
   to - Написать в MAX первым (в группе)
   support - Написать в поддержку
   help - Справка
   ```

### 2. Ключ шифрования

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Ключ шифрует токены MAX в базе. Потеряете ключ — всем придётся заново войти по QR.

### 3. Запуск в Docker

```bash
cp env.example .env   # впишите TG_BOT_TOKEN и ENCRYPTION_KEY
docker build -t max-bridge .
docker run -d --name max-bridge --restart unless-stopped \
  --env-file .env \
  -v max-bridge-data:/data \
  max-bridge
```

Каталог `/data` обязательно держите на постоянном томе: там база с токенами, группами и маппингом сообщений. Без тома каждый пересбор контейнера стирает все подключения.

Бот работает через long polling — входящие порты не нужны. HTTP-сервер на `:8080` отдаёт `GET /api/health` для проверки живости; публиковать его наружу незачем.

### Без Docker

```bash
uv venv && uv pip install -e '.[dev]'     # или: python -m venv .venv && pip install -e '.[dev]'
set -a; source .env; set +a
python -m max_bridge
```

Нужен Python 3.12+. Для локального запуска поменяйте в `.env` `DB_PATH` на `data/bridge.db`.

## Конфигурация

| Переменная | Обязательна | По умолчанию | Что это |
|---|---|---|---|
| `TG_BOT_TOKEN` | да | — | Токен бота от @BotFather |
| `ENCRYPTION_KEY` | да | — | Fernet-ключ для токенов MAX |
| `DB_PATH` | нет | `data/bridge.db` | Путь к SQLite (в Docker — `/data/bridge.db`) |
| `ADMIN_TG_ID` | нет | `0` | Telegram ID админа: ему приходят `/support`, он отвечает Reply. `0` — поддержка выключена |
| `LOG_LEVEL` | нет | `INFO` | На `DEBUG` в лог попадают фрагменты сообщений и контактов |
| `API_HOST` / `API_PORT` | нет | `0.0.0.0` / `8080` | HTTP-сервер (`/api/health`) |
| `POSTHOG_API_KEY` | нет | — | Аналитика команд в PostHog; без ключа выключена |
| `POSTHOG_HOST` | нет | `https://eu.i.posthog.com` | Инстанс PostHog |

С включённой аналитикой в PostHog уходят Telegram ID, username и имя пользователей бота, названия команд и шаги онбординга; тексты сообщений не уходят.

## Команды

| Команда | Где | Что делает |
|---|---|---|
| `/start` | личка | Подключение: QR-вход, затем настройка группы |
| `/login` | личка | Заново войти в MAX по QR |
| `/status` | личка | Статус подключения |
| `/stop` | личка | Приостановить пересылку |
| `/support <текст>` | личка | Сообщение админу (`ADMIN_TG_ID`); ответ админа Reply-ем вернётся пользователю |
| `/help` | личка | Справка |
| `/setup` | группа | Создать 4 темы и запустить пересылку |
| `/to <кому> [текст]` | группа | Написать в MAX первым |

`/to` ищет по контактам и названиям групп: все слова запроса должны совпасть, регистр и «ё» не важны. Кому писать — самая длинная начальная часть запроса, под которую кто-то нашёлся; если в команде есть перенос строки, первая строка — адресат, остальное — текст. Несколько совпадений — бот предложит кнопки. Номер телефона ищется отдельным запросом к MAX. Ответ Reply на сообщение `→ Имя: текст` продолжает переписку.

## Протокол MAX

WebSocket `wss://ws-api.oneme.ru/websocket`, кадры JSON `{ver, cmd, seq, opcode, payload}`; `cmd` 0 — запрос или push, 1 — успешный ответ, 3 — ошибка.

| Opcode | Назначение |
|---|---|
| 1 | heartbeat |
| 6 | handshake (`deviceId`, `userAgent`) |
| 19 | вход токеном → снапшот: профиль, контакты, чаты |
| 32 | имена контактов по id |
| 46 | поиск пользователя по телефону |
| 48 | тип и название чатов по id |
| 64 | отправка / входящее сообщение |
| 128 | push с новыми сообщениями |
| 288 / 289 / 291 | QR-вход: получить QR, статус, забрать токен |

QR-вход MAX отдаёт только клиенту с полным web-userAgent и актуальной `appVersion` (`WEB_USER_AGENT` в `src/max_bridge/max_client.py`); иначе ответ `qr_login.disabled`. Если QR перестал работать — первым делом обновите `appVersion` до текущей версии web.max.ru.

Chat id личного диалога = `мой_id XOR id_собеседника`, поэтому написать можно и тому, с кем переписки ещё не было.

## Структура

```
src/max_bridge/
├── __main__.py         # точка входа: python -m max_bridge
├── config.py           # переменные окружения
├── bot.py              # Telegram-бот (aiogram 3): онбординг, /setup, /to, ответы
├── qr_login.py         # QR-вход в MAX собственным устройством
├── max_client.py       # WebSocket-клиент MAX: handshake, снапшот, запросы, heartbeat
├── session_manager.py  # по MaxClient на пользователя, перезапуски, отзыв токена
├── router.py           # MAX → нужная тема Telegram, фото альбомами
├── outbound.py         # поиск адресата для /to
├── db.py               # SQLite: users, user_groups, message_mapping, max_chats, …
├── crypto.py           # Fernet-шифрование токенов
├── api.py              # /api/health (+ устаревший /api/pair)
└── analytics.py        # опциональный PostHog
docs/GUIDE.md           # инструкция для пользователя бота
```

`/api/pair` и коды привязки остались от первой версии, где токен забирался из браузера расширением; новые подключения идут только через QR.
